# Installation engine comparison (Story 2.1, Track 1)

Question: which installation engine, Archinstall JSON/CLI or native Arch commands, should
populate `install/engine/apply`, judged against one shared fixed reference-VM scenario?

This comparison is not itself a decision. The user decided at the checkpoint and the outcome is
recorded in [ADR 0002](../../docs/adr/0002-installation-engine-selection.md): native Arch commands are
selected, combining this evidence with the maintainer's preference. The Archinstall prototype remains as
evidence only.

Prototypes:

- [`archinstall-json-cli/`](archinstall-json-cli/README.md)
- [`native-arch/`](native-arch/README.md)

Raw results: `evidence/prototypes/installation/<engine>/<run-id>/` (ignored).

### Upstream change exposure

Pinned source review, made after the counted runs. It is source-reviewed, not measured.

- Archinstall: tag `4.5` is commit `78982a624824aa415f59bf88c515676a589e3c55`. Release dates: `v2.8.6`
  2024-08-28, `v3.0.0` 2024-11-17, `3.0.15` 2025-12-31, `4.0` 2026-03-30, `4.5` 2026-09-29. Only
  `archinstall/lib/args.py` was compared across tags (`3.0.15`, `4.0`, `4.5`); `v2.8.6` has no such file,
  so the configuration parser could not be compared with it. Other models were not compared.
- Configuration keys this prototype uses that changed shape: `parallel_downloads` (top level in `3.0.15`
  and `4.0`) became `pacman_config` in `4.5` (commit `80da3f14`), and `4.5` still reads the old key in
  a path marked `DEPRECATED`. The same function keeps `DEPRECATED` paths for `bootloader` plus `uki`
  (now `bootloader_config`), `!users`, and `!root-password` (now the hash forms the prototype uses).
- The user interface changed from `curses` to `Textual` in `4.0` (release notes). It matters for the
  interactive path only; the prototype's unattended path uses no menu.
- The `3.0.8` release notes list breaking changes to internal Python calls (`storage['session']`,
  `storage['LOG_PATH']`); the prototype uses neither.
- Not reviewed: the other configuration models across versions, so the absence of other key changes
  is not established.
- `arch-install-scripts`: releases `v28` 2022-11-20, `v29` 2024-10-20, `v30` 2025-09-23, `v31`
  2025-09-30. Between `v28` and `v31` the options the prototype uses (`pacstrap -K`, `genfstab -U`,
  `arch-chroot DIR COMMAND`) are unchanged; the diff adds `-S` and `-r` to `arch-chroot` and `atgc`
  handling to `genfstab`. `bootctl` was not source-reviewed.
